### 2. Root Causes Found
- **Silent J and V:** Letters were previously routed to `speak_character` instead of the word speech path. When sent as raw characters to sherpa-onnx MMS-TTS Tagalog (`tgl`), the engine dropped unsupported phonemes 'j' and 'v' (missing from indigenous Abakada/Tagalog tokens), and because no pre-rendered word WAV existed, the call failed silently. Routing letters through the same speech call as words using phonetic orthography resolved the silence.
- **Word Pauses:** Filipino sentences were using concatenative playback with large per-word gaps (30-80 ms), and AI Assistant text was parsed without uniform whitespace normalization. Defining a unified 10 ms inter-word gap with 150 ms comma and 300 ms sentence pauses restored natural continuous prosody.
- **Bluish Live Preview:** Picamera2 was configured with `RGB888`, which outputs RGB byte order into NumPy arrays, but `ili9488_display.py` was reversing channels (`arr[:, :, ::-1]`), assuming BGR input. This caused a red/blue channel swap resulting in a blue tint.
- **Scanner Audit:** The previous scanner attempted global page lattice fitting over the entire frame with aggressive quality gates (Laplacian variance, sparse line checks) that failed on real camera frames with printed text, borders, or non-uniform lighting.

### 3. Assumptions Made
- Braille indicators (capital indicator dot 6 alone and number sign dots 3-4-5-6) are ignored from spoken letter readouts so Grade 1 spelling remains focused on letter names and word pronunciation.
- Uncontracted Grade 1 Braille words are positioned within the central 50% width and 40% height of the camera frame.

### 4. Tasks Left PARTIAL or BLOCKED
- **None**. All 4 tasks completed with status **DONE**.

## Direct USB Keyboard (No SSH)
- **Status:** DONE (implemented, tested, documented)
- **Architecture found (before this change):** `brailce/core/app.py` setup read `config.input_device` but ONLY `"keyboard"` was honored - every other value fell back to the same `KeyboardInputDevice` (`brailce/input/keyboard_input.py`). That device has two paths: (1) a `keyboard`-library hook (`kb.on_press`) that silently fails on the Pi because `keyboard` is NOT in `requirements-pi.txt`, and (2) a raw-terminal stdin listener that only starts when `sys.stdin.isatty()` - under `brailce.service` (root systemd unit, stdin = /dev/null) this is always False. NET RESULT: under the service, NEITHER path ran - a USB keyboard plugged into the Pi did NOTHING without an SSH/PuTTY session.
- **New direct device path:** `brailce/input/evdev_input.py` - `EvdevInputDevice(KeyboardInputDevice)` reads USB keyboards directly from `/dev/input/event*` via python-evdev. It enumerates devices exposing EV_KEY codes in the standard keyboard window (codes 1..126; mice live at BTN_* >= 256 so they are excluded), GRABs each keyboard (EVIOCGRAB, no console leak), translates evdev keycodes to the SAME normalized key names the hook/terminal paths produce ("a", "f1", "space", "esc", "ctrl+q", ...) and dispatches through the NEW shared `KeyboardInputDevice._dispatch_key_name` - a single event vocabulary, so ALL existing behavior (Esc -> STOP_PRESSED per JOB 1, Ctrl+C/Ctrl+Q -> QUIT, F1/F2/F3 mode/language/clear, F11/F12 volume, characters) works identically. Modifier tracking (left/right ctrl/shift/alt) powers Ctrl+C/Ctrl+Q combos and Shift-row symbols (! @ # ... ?).
- **Hotplug tolerance:** the background loop re-enumerates every 5 s while no keyboard is found and after any read error (unplug), so the keyboard can be plugged in before or after boot without restarting the service; it never crashes when no device is present (the service still starts and the terminal path is unaffected).
- **No-SSH guarantee:** `create_input_device()` selection - `"keyboard"` (default) AUTO: evdev device when evdev is importable + a USB keyboard is present, OR headless (no TTY, i.e. the systemd service - never blocks on stdin); legacy device otherwise (interactive TTY without USB keyboard = unchanged behavior). `"evdev"` forces the direct path, `"terminal"` forces the legacy hook/stdin path, unknown values keep the existing warning+fallback. The terminal listener only engages when a real TTY is attached (`isatty`), so PuTTY remains usable for debugging.
- **Config:** `input.device` semantics above + new `input.usb_name_match` (optional case-insensitive substring filter on the device name, "" = any keyboard) in `brailce/config/defaults.py` + `brailce/config/config.json`. `requirements-pi.txt` gains `evdev>=1.6.0`.
- **Tests:** new `brailce/tests/test_evdev_input.py` (59 tests, fully mocked evdev - no real /dev/input needed): (a) keycode -> event translation (letters/digits/numpad/punctuation+math, Space, Enter+KPENTER, Backspace, Esc -> STOP_PRESSED not QUIT, F1/Tab -> MODE, F2/` -> LANGUAGE, F3/Delete -> CLEAR, F11/F12 volume, release+autorepeat ignored, unknown codes ignored, non-EV_KEY ignored); (b) modifier tracking (both ctrl keys, Ctrl+C and Ctrl+Q -> QUIT, ctrl-release restores, ctrl+other ignored, both shift keys, Shift+1 -> "!", Shift+/ -> "?", Shift+3 -> "#", Shift+` -> "~" language toggle, alt combos ignored); (c) auto-selection with mocked evdev (unavailable -> legacy, USB present -> evdev, interactive TTY w/o USB -> legacy, headless w/o USB -> evdev, forced "evdev"/"terminal", unknown -> legacy, name_match passthrough, defaults asserted); (d) no-device start/stop does not crash + read-error re-enumerates without crashing; (e) enumeration (keyboard GRABbed + mouse excluded, name filter, empty filter, grab-failure tolerated, list_devices error -> empty, None module -> empty). ## Safe Shutdown: Ctrl+P + GPIO long-press
- **Status:** DONE (implemented, tested, documented)
- **Why:** the device is headless (no SSH needed) - power-ON is automatic (boot -> `brailce.service`), but power-OFF must be SAFE: never an abrupt power cut (SD corruption), always a clean `systemctl poweroff`. Two trigger paths: the `Ctrl+P` keyboard combo (USB keyboard / PuTTY / laptop) and an optional GPIO long-press button for users who wire their power switch to a GPIO pin.
- **Event:** `EventType.SHUTDOWN_PRESSED` added to `brailce/core/events.py` (control-events group, `auto()` style next to `STOP_PRESSED`).
- **Keyboard paths (same dispatch style as Ctrl+Q -> QUIT):** terminal raw path `brailce/input/keyboard_input.py` - Ctrl+P is byte `\x10`, mirrored after the existing Ctrl+C (`\x03`) / Ctrl+Q (`\x11`) handling (stops the listener, emits the event); shared hook/evdev dispatch `_dispatch_key_name` gains `ctrl+p` next to `ctrl+q`; the direct USB evdev path (`brailce/input/evdev_input.py`) translates Ctrl+P into the `ctrl+p` key name through the SAME shared dispatch - one vocabulary, zero duplicated logic. Documented in-code: `Ctrl+P` = safe shutdown; `Ctrl+C`/`Ctrl+Q` = quit the app to the shell (unchanged).
- **App handler (`brailce/core/app.py`):** `SHUTDOWN_PRESSED` -> `_handle_shutdown_pressed()`, guarded by a one-shot flag (repeated presses/holds ignored). Flow: (1) localized announcement via the NORMAL speech queue, non-interrupting (`speak_text(..., interrupt=False)`) + shown on the display; (2) bounded wait (up to 5 s) for the announcement to actually play - `_wait_for_speech_to_drain()` polls the speech stack's existing mechanisms (Piper/eSpeak/Filipino engine queues empty AND `AudioDeviceCoordinator` has no active playback process); (3) the EXISTING app cleanup path `shutdown()` (same as QUIT: poller, input, speech, display, camera); (4) `_power_off()`: `systemctl poweroff` in subprocess list-form, output suppressed, falling back to `shutdown -h now` when systemctl is missing; every step's errors are logged, never fatal to the flow.
- **Strings (`brailce/i18n/strings.py`):** `SHUTDOWN_ANNOUNCE` - EN "Shutting down. Goodbye." / FIL "Pinapatay na ang Brailce. Paalam." (same style as the battery strings). DEVIATION: the requested FIL wording "Nagpapatay..." has no cached WAV in the frozen `brailce/audio/filipino` word bank (the `test_all_filipino_math_i18n_ai_words_have_cached_audio` invariant tokenizes ALL FIL string templates), so the banked verb "pinapatay" (same verb as the existing APP_SHUTDOWN string, same meaning) was used - all five tokens resolve to the bank.
- **GPIO long-press (`brailce/input/shutdown_button.py`, new):** `ShutdownButton(InputDevice)` wires a gpiozero `Button` with `hold_time` from config; the hold callback emits ONE `SHUTDOWN_PRESSED` through the app's normal event callback - no shutdown logic duplicated. gpiozero imported lazily inside `start()`; unavailable/module-missing or `shutdown_gpio: null` -> ONE INFO log, service boots fine everywhere (verified on this Windows host).
